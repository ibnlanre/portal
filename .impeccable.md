## Design Context

### Users

React and TypeScript developers building applications whose state grows beyond a few shallow hooks. They need to understand quickly how Portal lets them read, update, and compose deeply nested state without losing a coherent store model.

### Brand Personality

Precise, composed, and developer-first. The experience should inspire confidence through accurate examples and useful interactions rather than marketing claims or decorative novelty.

### Aesthetic Direction

Restrained technical editorial design. Portal owns a visual language of paths, branches, nested nodes, and focused state scopes. Use this sparingly as the product identity; avoid generic developer-landing-page signals such as glowing gradients, status pills, repetitive icon-card grids, and broad competitor scorecards. Support both light and dark themes.

### Design Principles

1. Make the nested, composable store model tangible in the first viewport.
2. Prefer runnable-looking, technically correct examples over generic marketing statements.
3. Build trust with narrow, defensible claims and clear trade-offs.
4. Let structure and interaction create identity; typography and color support it rather than replace it.
5. Preserve a calm, legible documentation experience across desktop and touch devices.
