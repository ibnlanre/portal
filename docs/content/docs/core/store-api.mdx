Every store made by `primitive`, `composite` or `collection`, and every branch of
a composite, has the same members.

| Member                           | Use                                          |
| :------------------------------- | :------------------------------------------- |
| `$get()` / `$get(select)`        | Read the value, or select from it.           |
| `$use()` / `$use(select, deps?)` | Read in a component and re-render on change. |
| `$set(value)` / `$set(updater)`  | Write.                                       |
| `$subscribe(fn, options?)`       | Listen; returns an unsubscribe.              |
| `$reset()`                       | Back to the initial value.                   |
| `$dispose()`                     | End the store.                               |
| `$onDispose(cleanup)`            | Run a cleanup when the store is disposed.    |

These names are reserved: a key of a `composite` shape may not use them.

## Reading: `$get()`

```ts
const app = composite({ user: composite({ name: "A" }), count: 0 });
app.$get(); // { user: { name: "A" }, count: 0 }
app.user.name.$get(); // "A"
app.$get((state) => state.count);
```

A read returns the store's own value with the type you gave it, stable by
identity until it changes. It is shared: do not mutate it. See
[Reading state](/docs/core/reading-state).

## Writing: `$set()`

```ts
app.count.$set(1);
app.count.$set((count) => count + 1);
app.$set({ user: { name: "B" } }); // merges into branches
```

See [Setting state](/docs/core/setting-state) for what a write means for each kind.

## Listening: `$subscribe()`

```ts
const stop = app.user.$subscribe((user) => console.log(user));
stop();
```

The current value is delivered at once unless the second argument is `{ immediate: false }`.
See [Subscriptions](/docs/core/subscriptions).

## Lifecycle

`$reset()` returns a store (every branch, for a composite) to its initial value
and notifies. `$dispose()` ends it: it drops its subscribers, runs the cleanups
registered with `$onDispose()`, and makes later writes no-ops. Reads keep
returning the last value, and it is safe to call twice. The creator disposes:
disposing a composite disposes the leaves it made itself, unsubscribes from every
store it was handed, and leaves those alive, including a store created inline in
the shape (dispose that one as `app.cart.$dispose()`). Disposing a store that
others hold leaves them able to read its last value; writes to it are no-ops.

`$onDispose(cleanup)` ties work to a store's lifetime and returns a function
that removes the cleanup. A cleanup registered on an already-disposed store runs
at once.

```ts
const timer = setInterval(() => app.count.$set((n) => n + 1), 1000);
app.$onDispose(() => clearInterval(timer));
app.$dispose(); // clears the timer
```

## Batching

`batch(fn)` is a top-level function, not a store method. Writes made inside `fn`,
to any stores, are one outermost write: subscribers are called at most once,
after `fn` returns. Nested calls join the outer one, and if `fn` throws the
writes already applied stay and delivery still happens once. If both `fn` and
delivery throw, an `AggregateError` is thrown with `[fn's error, delivery's
error]`, so neither is masked.

```ts
import { batch } from "@ibnlanre/portal";

batch(() => {
  cart.$reset();
  cart.$set(next); // replace everything: subscribers hear one change
});
```

## Connection and sharing

A store is an individual: it knows nothing about who holds it. A composite
connects to each store in its shape by subscribing to it, and the same store can
be a branch of any number of composites. Nothing is copied:

```ts
const a = composite({ n: 1 });
const c = composite({ a });
const d = composite({ a, other: primitive("x") });

c.a === a && d.a === a; // true
a.n.$set(2); // c and d both see it
```

Shapes are fixed at construction, so connections can only point at stores that
already exist and a cycle cannot be built. Writes pass through: a partial `$set`
on a composite writes each listed branch by that branch's own rule and
leaves the others alone, and `$reset()` resets every branch. Because a
shared branch is the same store, these also change the other composites that
hold it. To get independence, build a second store.

A subscriber is called at most once per outermost write, even when the write
reached it along several paths.

A composite connects to its branches until it is disposed. One that is never
disposed stays reachable from every branch it holds, so a composite built on
every render and never disposed leaks into any long-lived branch it shares.
After `composite.$dispose()`, a write to a shared branch no longer reaches it.

Every store is frozen: adding, deleting or defining a property throws. A
composite's enumerable keys are its branches and methods; the `$` members are
hidden.

## Collections

`collection(make)` is callable and has `$has(key)`, `$keys()`, `$delete(key)` and
`$clear()` besides the members above.

```ts
const drafts = collection((id: string) =>
  composite({ lines: primitive<string[]>([]) })
);
drafts("acme"); // made on first use
drafts.$keys(); // ["acme"]
drafts.$delete("acme"); // resets that entry, then disposes it
drafts.$clear(); // resets and disposes all
```

`$delete` and `$clear` reset each removed entry to its initial value in the same
write, so anything holding it (a mounted component, a subscriber) sees the empty
state, and then dispose it. A persisted collection also removes the entry's
stored key, but only for live entries (those created in this visit); `entry.$dispose()` alone leaves it. Stored keys of entries that were never created are
left in storage: sweep them yourself, as the persistence guide shows. See
[Persistence](/docs/guides/persistence).

Keys are plain strings, as object keys always are: `make` receives a `string`, `drafts(1)` is a type error, and `$keys()` is a `string[]`. A numeric id needs `String(id)` at the call site. An entry made by
reading does not notify, because reading must never cause an update (it can run
during a render). A collection's `$get()` and `$keys()` reflect the entries that
exist. `$set`, `$reset`, `$delete`, `$clear`, `entry.$dispose()` and a change to an
entry's own value notify. `drafts.$set({ acme: state })` creates an entry explicitly and notifies.
