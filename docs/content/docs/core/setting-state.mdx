## Primitives swap

`$set` on a primitive swaps the whole value. It never merges, even for objects:

```ts
const settings = primitive<{ a?: number; b?: number }>({ a: 1, b: 2 });
settings.$set({ a: 3 });
settings.$get(); // { a: 3 }
```

The updater form receives the current value and must return a new one:

```ts
const count = primitive(0);
count.$set((current) => current + 1);
```

To store a function in a primitive, give the initializer `() => fn` and write
with an updater. A function passed to `$set` is treated as an updater.

## Composites merge

A write to a composite with a partial state merges into its branches. Branches
the state omits are left alone:

```ts
const app = composite({
  count: 0,
  user: composite({ age: 1, name: "A" }),
});
app.$set({ user: { name: "B" } });
app.$get(); // { count: 0, user: { age: 1, name: "B" } }
```

Declared keys are structural: they are never dropped, and keys you did not
declare are ignored. A composite branch recurses; a primitive branch, including
a leaf that holds an object, is swapped whole. The argument is typed per key from
your declaration, so methods are not accepted and there is no `DeepPartial` over
your own types.

## Replacing everything

There is no replace option. Replacing everything is `$reset()` and then
`$set(value)`. Wrap the pair in `batch` so subscribers hear it once, after both:

```ts
import { batch } from "@ibnlanre/portal";

batch(() => {
  app.$reset();
  app.$set({ count: 5, user: { name: "C" } });
});
// user.age is back to its initial value, 1
```

## Batching

`batch(fn)` runs `fn` as one outermost write, whichever stores it writes to.
Everything written inside is applied at once, and each subscriber is called at
most once, after `fn` returns. Nested `batch` calls join the outer one. If `fn`
throws, the writes already applied stay applied and delivery still happens once.

## Resetting

`$reset()` returns a store to its initial value; on a composite it resets every
branch. A primitive returns to its initial reference.

## Collections

```ts
drafts.$set({ acme: { lines: ["a"] } }); // writes listed entries, making missing ones
drafts.$delete("acme"); // removing is explicit
drafts.$clear(); // or $reset(): disposes every entry
```

## Updaters that throw

An updater runs before anything is written, so a throwing updater publishes
nothing.
