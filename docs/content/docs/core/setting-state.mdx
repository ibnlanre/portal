`$set` merges plain-object updates into the current store value and replaces
non-object values such as numbers, strings, and arrays. Use it on the leaf when
you have one value to change, or on the branch when the update belongs together.

You can also pass a **selector function** that receives the current value and returns the new value:

```ts
import { createStore } from "@ibnlanre/portal";

const countStore = createStore(0);

// Set directly
countStore.$set(5);

// Update based on previous value
countStore.$set((prev) => prev + 1);
```

## Object merging

When you pass a plain object to `$set`, it's deep-merged into the current state:

```ts
const store = createStore({ settings: { theme: "dark", fontSize: 14 } });

// Merges: theme is updated, fontSize is kept
store.settings.$set({ theme: "light" });
// Result: { theme: "light", fontSize: 14 }
```

The deep merge is powered by `combine()`, which is also available directly:

```ts
import { combine } from "@ibnlanre/portal";

const merged = combine({ a: 1 }, { b: 2 }); // { a: 1, b: 2 }
```

## Union Values

Sometimes a single value needs to be one of several types — like a number or an object. `createStore()` derives the store type from the initial value, so when that value's type is a union, declare it explicitly (via a type argument or `as`), and the store is a `PrimitiveStore`.

```ts
const store = createStore<number | { count: number }>(5);

// store is PrimitiveStore<number | { count: number }>

store.$get(); // 5
store.$set(42); // now a number — valid
store.$set({ count: 10 }); // now an object — also valid
```

This is intentional. A union means the value can be _any_ branch at any time. Because the initial value is a primitive, `store` is a `PrimitiveStore` — exposing typed dot-access on a value that could be a number tomorrow would be unsound.

If you need typed dot-access, seed the store with an object (e.g. `createStore({ count: 5 })`) so a `CompositeStore` is created — a primitive-backed store can't expose property access.

## Clearing values and preserving keys

`$set` deep-merges plain objects and replaces other values, including arrays,
`null`, and `undefined`. Omitted object keys survive a merge. Setting a property
to `undefined` retains its key; it does not delete it. Direct assignment or
`delete` on a store proxy does not mutate state. Portal does not currently expose
an explicit object-replacement or key-deletion method.
