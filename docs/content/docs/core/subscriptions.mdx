Use `$subscribe()` for side effects outside React: persistence, logging, and
integration work. Subscribe to the narrowest branch that owns the concern.

```ts
import { createStore } from "@ibnlanre/portal";

const store = createStore({ count: 0 });

const unsubscribe = store.$subscribe((state) => {
  console.log("State changed:", state);
});
```

## Immediate invocation

By default, `$subscribe` fires immediately with the current value.
Pass `false` as the second argument to only react to _future_ changes:

```ts
// Only runs on subsequent changes
store.$subscribe(handler, false);
```

## Unsubscribing

`$subscribe` returns an unsubscribe function. Call it to stop listening:

```ts
const unsub = store.$subscribe(handler);

// Later...
unsub();
```

## Subscribing to nested paths

Composite stores let you subscribe to a specific nested node —
you only get notified when that branch changes:

```ts
store.settings.$subscribe((settings) => {
  console.log("Settings updated:", settings);
});

store.user.preferences.theme.$subscribe((theme) => {
  console.log("Theme changed:", theme);
});
```

This is more efficient than subscribing to the root and filtering by path.

## SSR safety

`$subscribe` works during server-side rendering. Subscribers fire
synchronously when `$set` is called, so state is always consistent
before the render completes.

## Delivery and errors

Delivery is synchronous and follows commit order. If a listener writes again
while a notification is being delivered, the nested write is queued behind the
current batch: no subscriber sees a newer snapshot and then an older one.

A listener that throws does not strand the listeners registered after it. The
remaining listeners still receive the committed value, and the error surfaces
after delivery: a single failure is rethrown as-is, and multiple failures are
reported together as an `AggregateError`. When an immediate callback throws
during subscription, the subscription is removed before the error propagates.

## Notification boundaries

Raw subscriptions are write-based. A write notifies the addressed path, its
ancestors, and all subscribed descendants, including descendants cleared to
`undefined`. A root write notifies every subscriber. Unrelated sibling paths do
not fire. Every successful `$set()` notifies these raw subscribers, including same-value
leaf writes, empty object merges, and object merges whose contents are unchanged.
React selector equality is a separate contract.
