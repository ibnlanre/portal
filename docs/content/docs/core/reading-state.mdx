## Typed as given

A store never rewrites your types. Whatever you put in comes back with the same
type: a branded id, a `Date`, a class instance, an interface, a union, a tuple, a
`Map`.

```ts
type Id = string & { __brand: "Id" };
const selected = primitive<Id | null>(null);
selected.$get(); // Id | null
```

## Stable, shared values

Portal does not copy your values. `$get()`, `$use()`, selectors and subscribers
share the store's own values: the reference you put in is the reference you read
back. Use `$set()` to change state; do not mutate a read. Reads are not frozen at
runtime, so the rule is yours to follow.

Repeated reads return the same reference until that store changes. A
composite's `$get()` is rebuilt from its branches when one changes, and every
untouched subtree keeps its identity:

```ts
const app = composite({
  left: composite({ value: 1 }),
  right: composite({ value: 1 }),
});
const before = app.$get();
app.left.value.$set(2);
app.$get().right === before.right; // true
```

## What a composite reads as

A composite reads as an object of its branches' states and its leaves' values.
Methods are not state, so they are left out.

```ts
const app = composite({ title: "", add() {} });
app.$get(); // { title: "" }
```

## Selecting

`$get(select)` and `$use(select)` pass the value to a selector. A selector may
allocate a derived result, but anything it keeps from its input is still shared
store data. `$use` re-renders only when the selected result changes (`Object.is`).
