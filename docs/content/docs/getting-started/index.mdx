Portal is most useful when a feature needs a focused part of a larger state
tree. Create one root store, then treat a nested branch as a store in its own
right. The API stays the same at every level.

## Installation

You can add Portal to your project using your favorite package manager:

```bash
# npm
npm install @ibnlanre/portal

# pnpm
pnpm add @ibnlanre/portal

# yarn
yarn add @ibnlanre/portal
```

Using TypeScript? Good news—we include type definitions automatically, so you don't need to install any extra `@types` packages.

### Using a CDN

If you're not using a bundler, you can grab Portal directly from a CDN:

```html
<!-- Skypack -->
<script type="module">
  import { createStore } from "https://cdn.skypack.dev/@ibnlanre/portal";
</script>

<!-- unpkg -->
<script src="https://unpkg.com/@ibnlanre/portal"></script>

<!-- jsDelivr -->
<script src="https://cdn.jsdelivr.net/npm/@ibnlanre/portal"></script>
```

## Your first root store

`createStore` takes your state's initial value as its single argument — Portal infers the state's type directly from that value, so no schema is required.

```ts
import { createStore } from "@ibnlanre/portal";

const app = createStore({
  user: {
    profile: {
      name: "Alex",
      preferences: { theme: "dark", compact: false },
    },
  },
});

const preferences = app.$at("user.profile.preferences");

// This is a store scoped to that branch.
preferences.$set({ compact: true });
preferences.theme.$set("light");
```

## Reach a branch directly or by path

Use dot access when the path is known in code. Use `$at()` when a path is
assembled dynamically or passed into a reusable feature.

```ts
import { createStore } from "@ibnlanre/portal";

const app = createStore({
  user: {
    settings: {
      theme: "dark",
      notifications: { email: true, push: false },
    },
  },
});

app.user.settings.theme.$set("light");

const notifications = app.$at("user.settings.notifications");
notifications.$set({ push: true });
```

## Reacting to changes

You can listen at the root, a branch, or a leaf. Subscribe as close to the
work as possible so the callback receives the value it needs.

By default, the subscription runs immediately with the current value, so you don't miss anything.

```ts
const unsubscribe = countStore.$subscribe((newValue) => {
  console.log("Count is now:", newValue);
});

countStore.$set(10);
// Console: "Count is now: 10"

// Stop listening when you're done
unsubscribe();
```

## Using with React

If you're using React, Portal provides a unified `$use()` hook that serves as both a selector and a subscriber.

```tsx
import { createStore } from "@ibnlanre/portal";

const countStore = createStore(0);

function Counter() {
  // Automatically re-renders when countStore changes
  const [count, setCount] = countStore.$use();

  return <button onClick={() => setCount(count + 1)}>Count is {count}</button>;
}
```

## Core concepts

Here's a quick map of the concepts you'll use most often:

| Method            | Description                                                           |
| :---------------- | :-------------------------------------------------------------------- |
| **`createStore`** | Creates a new observable store from an initial value (type inferred). |

| **`$get`** | reads the current value (without subscribing). |
| **`$set`** | Updates the value (merges objects, replaces primitives). |
| **`$use`** | React hook to read values and re-render on changes. |
| **`$subscribe`** | Native subscription for non-React code (logs, analytics, etc). |
