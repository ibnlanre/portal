`$use()` is the React bridge. It works on the root store and on every nested
store, so a component can subscribe to the branch it renders instead of pulling
the whole application state into its boundary.

```tsx
import { createStore } from "@ibnlanre/portal";

const store = createStore({ count: 0 });

function Counter() {
  const [count, setCount] = store.count.$use();

  return <button onClick={() => setCount((c) => c + 1)}>Count: {count}</button>;
}
```

## Selectors for re-render gating

Pass a selector to subscribe to a derived value. Store updates trigger a render only when the selected result changes according
to `Object.is`. Parent renders and other hooks can still render the component.
A selector returning a fresh object or array counts as changed on a new source
snapshot, even when its contents are equal. Selecting an unchanged source
subtree preserves its identity across unrelated leaf writes. Treat returned
hook snapshots as read-only and change state through the setter.

```tsx
function SidebarStatus() {
  // Only re-renders if 'collapsed' changes
  const [isCollapsed] = store.sidebar.$use((s) => s.collapsed);

  return <div>{isCollapsed ? "Closed" : "Open"}</div>;
}
```

## Dependency arrays

When a selector depends on external values, pass them in the dependency array:

```tsx
function Greeting({ prefix }: { prefix: string }) {
  const [message] = store.name.$use((name) => `${prefix}: ${name}`, [prefix]);

  return <div>{message}</div>;
}
```

## Nested access

Composite stores expose nested nodes, each with their own `$use`:

```tsx
function Theme() {
  const [theme] = store.settings.theme.$use();
  return <div>Theme: {theme}</div>;
}
```

## Static usage

`$use()` follows the rules of hooks — call it at the top level of a
component or custom hook. The store identity is stable, so the selector
is the only thing that affects subscription behavior.
