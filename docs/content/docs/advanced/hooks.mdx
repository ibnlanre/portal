Portal includes utilities for the work around state: asynchronous requests,
memoized derived values, and dependency tracking. Use them when a component or
store action needs that behavior; the core store API remains the same.

## `useAsync`: Data Fetching Made Easy

Handling loading states and errors for async operations is repetitive. `useAsync` handles it for you.

It's perfect for fetching data inside your store actions.

```tsx
import { createStore, combine, useAsync } from "@ibnlanre/portal";

const state = { data: null };
const actions = {
  // A "hook action" that fetches data
  useFetchUser(id: string) {
    const { data, loading, error } = useAsync(
      async ({ signal }) => {
        const res = await fetch(`/api/users/${id}`, { signal });
        return res.json();
      },
      [id]
    );

    // Automatically sync successful data to the store
    if (data) {
      userStore.data.$set(data);
    }

    return { loading, error };
  },
};

const userStore = createStore(combine(state, actions));
```

Now your component is clean:

```tsx
function UserProfile({ id }) {
  const { loading, error } = userStore.useFetchUser(id);
  const [user] = userStore.data.$use();

  if (loading) return <Spinner />;
  if (error) return <Error msg={error.message} />;

  return <div>{user.name}</div>;
}
```

## `useSync`: Memoized Values with React Dependency Semantics

React's `useMemo` relies on referential equality: a dependency slot only counts
as changed when `Object.is` says so. `useSync` keeps exactly those semantics and
adds a `useMemo`-style factory signature, so derived values recompute when — and
only when — a dependency position actually changes. Reordering the same values,
or swapping in a new object, array, or function identity, counts as a change
even when the contents look equal.

```tsx
import { useSync } from "@ibnlanre/portal";

function Chart({ config }) {
  // `config` is an object like { color: 'red', points: [...] }.
  // Passing a new identity re-runs the calculation, matching useMemo:
  const processedData = useSync(() => {
    return expensiveCalculation(config);
  }, [config]);

  return <Graph data={processedData} />;
}
```

Store snapshots work well as dependencies because they keep their identity
between writes. Reading a branch and passing it as a dependency means the
calculation re-runs exactly when that branch changes:

```tsx
function Chart({ store }) {
  const [config] = store.config.$use();
  const processedData = useSync(() => expensiveCalculation(config), [config]);
  return <Graph data={processedData} />;
}
```

## `useVersion`: Dependency Tracking for Custom Hooks

If you're building your own hooks and want React's dependency behavior in one
place, `useVersion` is your friend. It returns a version number that increments
only when its input changes, comparing dependency arrays position by position
with `Object.is` — the same rule React applies to `useMemo`, `useEffect`, and
`useCallback` dependency lists.

```tsx
import { useVersion } from "@ibnlanre/portal";
import { useEffect } from "react";

function AutoSave({ draft }) {
  // A new `draft` identity counts as a change; the same value does not.
  const version = useVersion([draft]);

  useEffect(() => {
    console.log("Form changed! Saving...");
    saveToApi(draft);
  }, [version]); // Dependency is a simple number
}
```

Stable store snapshots pair naturally with this hook: `store.form.$get()`
returns the same object until that branch is written, so the version bumps
exactly when the form state changes.
