Use `cookieStorage` when you need direct cookie access instead of a store
adapter. It is appropriate for small browser-readable values; do not place
sensitive information in a cookie merely because it can be signed.

Portal exposes its internal cookie engine via `cookieStorage`. It handles the messy parts of `document.cookie` for you.

```ts
import { cookieStorage } from "@ibnlanre/portal";
```

## Basic Operations

### Reading Cookies

```ts
const token = cookieStorage.getItem("auth_token");
// returns "xyz..." or null
```

### Writing Cookies

```ts
cookieStorage.setItem("theme", "dark", {
  path: "/",
  maxAge: 3600 * 24 * 7, // 7 days
  secure: true,
  sameSite: "strict",
});
```

### Deleting Cookies

```ts
// Note: You must match the path/domain used when creating the cookie!
cookieStorage.removeItem("theme", { path: "/" });
```

### Clearing All Cookies

Wipes every cookie accessible to the current page.

```ts
cookieStorage.clear();
```

## Signing

Signing detects change. `cookieStorage.sign()` appends a hash of the value, and
`cookieStorage.unsign()` verifies it and returns the payload or `null`.

A secret delivered to the browser is readable by anyone who can run script on
the page or inspect the cookie itself. That means signing is **not a security
boundary against the browser's user**: it can catch accidental corruption and
naive edits by other code, but it cannot make a cookie trustworthy. Do not store
sensitive data — roles, tokens, entitlements — in a cookie merely because it is
signed, and keep authorization decisions on the server.

### `sign(value, secret)`

Creates a signed string that includes a hash of the value.

```ts
const safeValue = cookieStorage.sign("admin", "my-super-secret-key");
// Returns something like "admin.8a7b3c..."
```

### `unsign(value, secret)`

Verifies the signature. If the value was modified (or the signature doesn't
match), it returns `null`.

```ts
const value = cookieStorage.unsign(cookieValue, "my-super-secret-key");

if (value === null) {
  throw new Error("Cookie value failed verification");
}

console.log("Verified value:", value); // "admin"
```

Verification is not proof of origin. Treat a verified value the same way you
treat any other browser input — validate it where it is trusted.

## Cookie Options

When setting cookies, you can use these options:

| Option     | Type                          | Description                    |
| :--------- | :---------------------------- | :----------------------------- |
| `path`     | `string`                      | URL path prefix (default: `/`) |
| `maxAge`   | `number`                      | Lifetime in seconds            |
| `expires`  | `Date`                        | Absolute expiration date       |
| `secure`   | `boolean`                     | Only send over HTTPS           |
| `sameSite` | `'lax' \| 'strict' \| 'none'` | CORS policy                    |
| `domain`   | `string`                      | Domain scope                   |
