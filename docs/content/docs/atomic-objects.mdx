By default, Portal tries to be helpful by **merging** objects when you update them. This is usually what you want for state management.

But sometimes, you want an object to behave like a primitive value—when you set it, you want to **replace** it entirely.

This is where `createAtom()` comes in.

## Merging vs Replacing

Here's the default behavior (merging):

```ts
const store = createStore({
  settings: { theme: "dark", fontSize: 14 },
});

// Merges: theme is updated, fontSize is kept
store.settings.$set({ theme: "light" });
// Result: { theme: "light", fontSize: 14 }
```

Sometimes you want the opposite. You want to wipe the slate clean.

```ts
import { createStore, createAtom } from "@ibnlanre/portal";

const store = createStore({
  // Mark this object as "atomic"
  settings: createAtom({ theme: "dark", fontSize: 14 }),
});

// Replaces completely! fontSize is gone.
store.settings.$set({ theme: "light" });
// Result: { theme: "light" }
```

## When to use this

Atomic objects are perfect for:

- **API Responses**: When fetching new data, you usually want to replace the old data entirely, not merge it.
- **Strict Types**: When an object must exactly match a shape and shouldn't inherit usually undefined properties from previous states.
- **Resetting State**: When you want to clear specific sections of your store easily.

## Handling missing data with `fallback()`

If you're replacing objects, you might accidentally remove properties that your UI expects.

`fallback()` lets you provide default values when reading an atomic object, so you always get a complete shape back.

```ts
import { createStore, createAtom, fallback } from "@ibnlanre/portal";

// Define defaults once
const defaults = {
  theme: "light",
  fontSize: 14,
};

const store = createStore({
  // Initialize with defaults (or empty object)
  config: createAtom(defaults),
});

// Later, we accidentally set an incomplete config
store.config.$set({ theme: "dark" });
// store.config is now just { theme: "dark" }

// BUT, when we read it with fallback...
const safeConfig = store.config.$get(fallback(defaults));
// Result: { theme: "dark", fontSize: 14 }
```

The `fallback()` utility merges the current (potentially incomplete) state with your defaults, ensuring your selectors and components never crash due to missing keys.
